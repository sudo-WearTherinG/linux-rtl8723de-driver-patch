Realtek RTL8723DE Warm-Reboot Fix

Manual kernel source modification guide for the Bluetooth USB and Realtek PCIe Wi-Fi shutdown handlers.

1. Overview

This guide explains how to manually apply the RTL8723DE warm-reboot shutdown patch to the Linux kernel source.

The patch modifies two kernel source files:

File Purpose
drivers/bluetooth/btusb.c Bluetooth USB shutdown handling
drivers/net/wireless/realtek/rtw88/pci.c Realtek PCIe Wi-Fi shutdown handling

There are four modifications in total. Each modification below shows the original code and its replacement.

Important: Replace only the specified code. Do not replace entire source files with the excerpts shown here. Preserve the surrounding kernel source code.

Step 0: Download Your Running Kernel's Driver Source

Before editing the files below, download only the two affected driver folders matching your running kernel version: 

KVER=$(uname -r | cut -d'-' -f1)
git clone --depth 1 --filter=blob:none --sparse -b "v${KVER}" \
  https://kernel.googlesource.com/pub/scm/linux/kernel/git/stable/linux.git linux-rtw-fix
cd linux-rtw-fix
git sparse-checkout set drivers/bluetooth drivers/net/wireless/realtek/rtw88

1. Add Bluetooth Shutdown Flag

File: drivers/bluetooth/btusb.c
Location: Near the Bluetooth driver flag definitions, around line 990.

Add a new flag named BTUSB_NEEDS_SHUTDOWN_RESET.

Modification 1: Bluetooth flag definition
OLD CODE 
#define BTUSB_HW_SSR_ACTIVE    17
#define BTUSB_WAKEUP_BROKEN    18
#define BTUSB_RESET             19
NEW CODE 
#define BTUSB_HW_SSR_ACTIVE    17
#define BTUSB_WAKEUP_BROKEN    18
#define BTUSB_RESET             19
#define BTUSB_NEEDS_SHUTDOWN_RESET    20

The new flag tracks whether Bluetooth was opened during the current boot session.

2. Modify btusb_open()

File: drivers/bluetooth/btusb.c
Location: Inside static int btusb_open(struct hci_dev *hdev), immediately after the assignment to needs_remote_wakeup.
Modification 2: Track Bluetooth activation
OLD CODE 
data->intf->needs_remote_wakeup = 1;

if (test_and_set_bit(BTUSB_INTR_RUNNING, &data->flags))
    goto done;
NEW CODE 
data->intf->needs_remote_wakeup = 1;
set_bit(BTUSB_NEEDS_SHUTDOWN_RESET, &data->flags);

if (test_and_set_bit(BTUSB_INTR_RUNNING, &data->flags))
    goto done;

The new set_bit() call records that Bluetooth has been opened.

During shutdown, the flag determines whether the controller should undergo the Bluetooth shutdown reset sequence.

3. Add btusb_shutdown()

File: drivers/bluetooth/btusb.c
Location: Immediately before the declaration of static struct usb_driver btusb_driver.

Add the following complete function immediately before the btusb_driver structure.

Modification 3: New Bluetooth shutdown handler
OLD CODE 
static struct usb_driver btusb_driver = {
    .name       = "btusb",
    .probe      = btusb_probe,
    .disconnect = btusb_disconnect,
    .suspend    = pm_ptr(btusb_suspend),
    .resume     = pm_ptr(btusb_resume),
    .id_table   = btusb_table,
    .supports_autosuspend = 1,
NEW CODE 
static void btusb_shutdown(struct usb_interface *intf)
{
    struct btusb_data *data = usb_get_intfdata(intf);
    struct hci_dev *hdev;
    int err = -1;

    if (!data || intf != data->intf)
        return;

    hdev = data->hdev;
    data->intf->needs_remote_wakeup = 0;
    data->udev->do_remote_wakeup = 0;

    if (test_and_clear_bit(BTUSB_NEEDS_SHUTDOWN_RESET, &data->flags) &&
        hdev->shutdown) {
        err = usb_autopm_get_interface(data->intf);
        hdev->shutdown(hdev);
    }

    btusb_stop_traffic(data);
    usb_kill_anchored_urbs(&data->tx_anchor);

    if (!err)
        usb_autopm_put_interface(data->intf);
}

static struct usb_driver btusb_driver = {
    .name       = "btusb",
    .probe      = btusb_probe,
    .disconnect = btusb_disconnect,
    .shutdown   = btusb_shutdown,
    .suspend    = pm_ptr(btusb_suspend),
    .resume     = pm_ptr(btusb_resume),
    .id_table   = btusb_table,
    .supports_autosuspend = 1,

The replacement includes both the new shutdown function and the registration of that function in the USB driver structure.

Important: The .shutdown = btusb_shutdown entry is part of the replacement. Adding the function without registering it will not activate the shutdown handler.

Do not remove the remaining entries in the original btusb_driver structure. The excerpt above ends at .supports_autosuspend = 1 only to show the replacement location.

4. Modify rtw_pci_shutdown()

File: drivers/net/wireless/realtek/rtw88/pci.c
Location: Find the complete function void rtw_pci_shutdown(struct pci_dev *pdev), around line 1910.

Replace the entire existing function with the following implementation.

Modification 4: Wi-Fi PCI shutdown sequence
OLD CODE 
void rtw_pci_shutdown(struct pci_dev *pdev)
{
    struct ieee80211_hw *hw = pci_get_drvdata(pdev);
    struct rtw_dev *rtwdev;
    const struct rtw_chip_info *chip;

    if (!hw)
        return;

    rtwdev = hw->priv;
    chip = rtwdev->chip;

    if (chip->ops->shutdown)
        chip->ops->shutdown(rtwdev);

    pci_set_power_state(pdev, PCI_D3hot);
}
EXPORT_SYMBOL(rtw_pci_shutdown);
NEW CODE 
void rtw_pci_shutdown(struct pci_dev *pdev)
{
    struct ieee80211_hw *hw = pci_get_drvdata(pdev);
    struct rtw_dev *rtwdev;
    struct rtw_pci *rtwpci;
    const struct rtw_chip_info *chip;

    if (!hw)
        return;

    rtwdev = hw->priv;
    rtwpci = (struct rtw_pci *)rtwdev->priv;
    chip = rtwdev->chip;

    mutex_lock(&rtwdev->mutex);
    if (test_bit(RTW_FLAG_POWERON, rtwdev->flags)) {
        clear_bit(RTW_FLAG_RUNNING, rtwdev->flags);
        clear_bit(RTW_FLAG_FW_RUNNING, rtwdev->flags);
        rtw_power_off(rtwdev);
        clear_bit(RTW_FLAG_POWERON, rtwdev->flags);
    }
    else
        rtw_hci_link_ps(rtwdev, false);
    mutex_unlock(&rtwdev->mutex);

    rtw_pci_disable_interrupt(rtwdev, rtwpci);

    if (chip->ops->shutdown)
        chip->ops->shutdown(rtwdev);

    pci_set_power_state(pdev, PCI_D3hot);
}
EXPORT_SYMBOL(rtw_pci_shutdown);

This replacement adds explicit Wi-Fi power-off handling and PCI interrupt disabling before the existing chip shutdown callback and PCI power-state transition.

5. Verify the Modifications

After making all four changes, verify that the source files contain the new definitions and functions.

Bluetooth flag

grep -n "BTUSB_NEEDS_SHUTDOWN_RESET" \
    drivers/bluetooth/btusb.c

Bluetooth shutdown handler

grep -n -A 30 "static void btusb_shutdown" \
    drivers/bluetooth/btusb.c

Bluetooth driver registration

grep -n -A 12 "static struct usb_driver btusb_driver" \
    drivers/bluetooth/btusb.c

Wi-Fi shutdown handler

grep -n -A 35 "void rtw_pci_shutdown" \
    drivers/net/wireless/realtek/rtw88/pci.c
Source compatibility: The code excerpts correspond to the supplied kernel source and patch context. Kernel versions can change function signatures, structure definitions, and surrounding code. Do not assume that identical line numbers apply to other kernel versions.

6. Build and Install

From inside your modified kernel source directory (e.g., linux-rtw-fix), compile the two driver modules against your running kernel headers and copy them into updates/.

Compile the patched modules

make -C /usr/lib/modules/$(uname -r)/build M=$(pwd)/drivers/bluetooth modules
make -C /usr/lib/modules/$(uname -r)/build M=$(pwd)/drivers/net/wireless/realtek/rtw88 modules

Install to updates/ and refresh module map

sudo mkdir -p /usr/lib/modules/$(uname -r)/updates
sudo cp drivers/bluetooth/{btusb,btrtl,btmtk,btintel,btbcm}.ko /usr/lib/modules/$(uname -r)/updates/
sudo cp drivers/net/wireless/realtek/rtw88/rtw88_pci.ko /usr/lib/modules/$(uname -r)/updates/
sudo depmod -a

Once installation completes, perform a complete shutdown and power the machine back on.

Verify active modules

modinfo btusb rtw88_pci | grep -E "filename|srcversion"

Both modules should resolve to: 

/lib/modules/$(uname -r)/updates/

Rollback

To remove the patched modules and return to the stock kernel modules: 

for mod in btusb btrtl btmtk btintel btbcm rtw88_pci; do
    sudo rm -f "/usr/lib/modules/$(uname -r)/updates/${mod}.ko"
done
sudo depmod -a
